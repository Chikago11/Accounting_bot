# Accounting bot

Telegram-бот учёта расходов в Google Sheets: категории, месячный отчёт,
отдельные бюджеты Андрея и Макса. Вход разрешён только `ALLOWED_USER_IDS`.

## Запуск

Python 3.12, зависимости из `requirements.txt`:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
chmod 600 .env service_account.json
.venv/bin/python main.py
```

Заполните `.env`: токен, `SPREADSHEET_ID` существующей таблицы, JSON-ключ Google
и разрешённые Telegram ID. ID берётся из адреса `.../spreadsheets/d/<ID>/edit`.
При пустом ID сохранён старый поиск по `SPREADSHEET_NAME`; при указанном ID имя
не используется. Ошибка доступа по ID не переключает бота на другую таблицу.
Требуются первый лист с матрицей расходов и лист `andrei_mb`
(B1 — Андрей, B2 — Макс). Секреты и каталог `data/` исключены из Git.

`APP_TIMEZONE=Asia/Bangkok` задаёт общий часовой пояс для кнопок, отчётов и голоса,
в том числе при ручном запуске на сервере с UTC. Если `APP_TIMEZONE` не задан,
поддерживается прежний `VOICE_TIMEZONE`, затем используется `Asia/Bangkok`.
Часовой пояс проверяется при загрузке конфигурации, даже при выключенном голосе.
Опечатка в названии не позволяет запустить бота до исправления настройки.
Кнопки принимают только положительные суммы: прибавление или вычитание определяет
выбранное действие. Числовые ячейки читаются без оформления валюты и разделителей;
отображение заголовков месяцев пока должно оставаться `YYYY-MM`.
Версии прямых зависимостей зафиксированы; обновляйте их после проверки тестами.

При первой записи в новый месяц бот создаёт текстовый заголовок `YYYY-MM` и
формулу `SUM` в строке «Итого», найденной по названию. Диапазон суммы — от второй
строки до строки перед «Итого». Заголовок и формула отправляются одним
[пакетным запросом Sheets](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/batchUpdate).
Заранее заданная формула в «Итого» сохраняется. При занятых ячейках нового столбца
бот просит проверить таблицу. Существующие месяцы автоматически не переделываются.

Категория должна уже присутствовать в таблице в единственном экземпляре перед
«Итого». Недостающие строки бот не добавляет: добавьте категорию вручную и
проверьте диапазоны итоговых формул. Ошибка структуры выводится пользователю;
отклонённая голосовая операция отмечается как незаписанная.
При записи расхода в ячейку с ручной формулой бот использует её вычисленную сумму
и сохраняет новое итоговое число. Слагаемые не сохраняются.

На текущем сервере работает пользовательская служба с включённым linger:

```bash
systemctl --user status rich-family-bot
systemctl --user restart rich-family-bot
journalctl --user -u rich-family-bot -f
```

Штатная остановка через SIGINT завершает обработку и закрывает приложение без
traceback `KeyboardInterrupt`; остальные исключения не подавляются.

## Голосовой ввод

Отправьте боту голосовое, например:

- «Добавь расход на магазин тысячу бат и на бензин пятьсот бат».
- «Отмени расход на бензин двести бат».
- «Добавь в бюджет Макса триста бат и вычти из бюджета Андрея сто».
- «Вчера потратил на продукты пятьсот бат».

Бот покажет расшифровку и список операций. Запись начинается только после
«Подтвердить». «Изменить» отменяет пакет и предлагает меню или новое голосовое.
«Отмена» ничего не записывает. Неясная команда вызывает уточнение всего пакета.

Поддерживаются существующие операции: добавить/отменить расход, добавить/вычесть
из двух отдельных бюджетов. Доходы/зарплата, конвертация валют и новые категории
не добавлены. Отчёты и чтение остатков доступны прежними кнопками. Валюта — THB,
даты — Asia/Bangkok. Расходы можно отнести к дате за последние 366 дней; в таблице
они суммируются по месяцу. Отдельные бюджеты хранят текущий остаток без истории.

Ограничения: до 120 секунд, 10 МБ, 10 операций, 10 000 000 THB на операцию,
два десятичных знака. Подтверждение действует 15 минут. Одновременно распознаётся
одно голосовое; кнопочный интерфейс доступен во время распознавания.

## Архитектура

```text
Telegram voice → текущий бот → STT (GigaAM в Hermes)
  → Hermes без инструментов → строгий JSON → локальная проверка
  → SQLite pending → подтверждение → transactions.py
  → существующие google_api.py → Google Sheets
```

`catalog.py` — единственный список категорий для кнопок и модели.
`category_aliases.json` — редактируемые разговорные синонимы этих категорий.
Hermes получает только текст, категории, действия, валюту и время. Telegram-токен
и Google-ключ остаются в боте. Второй Telegram consumer не запускается.

`voice/providers.py` содержит интерфейсы STT/парсера и транспорт JSON через stdin.
На этом сервере `scripts/hermes_voice_bridge.py` установлен в существующий контейнер
Hermes. Общий API установленной версии не ограничивает инструменты отдельного
запроса, поэтому используется headless `AIAgent` с `enabled_toolsets=[]` и проверкой
пустого списка инструментов, без памяти и сохранения сессии. Провайдер и модель
берутся из текущей настройки Hermes, STT — из его настроенного GigaAM.

Этот адаптер зависит от установленного Python-интерфейса Hermes. После обновления
Hermes следует запустить smoke test. Транспорт можно заменить реализацией тех же
интерфейсов без изменения обработчиков и финансовых функций.

## Включение на сервере

Скопируйте адаптер в сохраняемый том уже работающего контейнера:

```bash
docker cp scripts/hermes_voice_bridge.py \
  hermes-agent-owxa-hermes-agent-1:/opt/data/scripts/accounting_voice_bridge.py
```

Задайте в `.env` параметры из `.env.example`: `VOICE_INPUT_ENABLED=true` и
`VOICE_BRIDGE_COMMAND` — JSON-массив аргументов. На текущем сервере эти параметры
задаются отдельным файлом `~/.config/systemd/user/rich-family-bot.service.d/voice.conf`:

```ini
[Service]
Environment=VOICE_INPUT_ENABLED=true
Environment='VOICE_BRIDGE_COMMAND=["docker","exec","-i","hermes-agent-owxa-hermes-agent-1","/opt/hermes/.venv/bin/python","/opt/data/scripts/accounting_voice_bridge.py"]'
TimeoutStopSec=240
```

Пользователь службы должен иметь доступ к Docker. После изменений:

```bash
systemctl --user daemon-reload
systemctl --user restart rich-family-bot
```

Для отключения установите `VOICE_INPUT_ENABLED=false` в том же drop-in и
перезапустите службу. Переменные systemd имеют приоритет над `.env`.
При выключенной функции дополнительные настройки не требуются, кнопки продолжают
работать. Каталог `data/` сохраняйте между обновлениями и перезапусками.

`TimeoutStopSec=240` даёт дополнительное время на штатное завершение работы.
При принудительной остановке запись восстанавливается как неопределённая по журналу.
Каждый запрос к адаптеру ограничен таймаутом; supervisor внутри контейнера
завершает зависший процесс и его дочерние процессы, удаляет временное аудио.

## Повторы и ошибки записи

SQLite сохраняет уникальность исходного сообщения, владельца пакета, срок действия
и результаты отдельных операций. Подтверждение атомарно переводит пакет в
`processing`; повторный callback возвращает результат. Рабочий процесс держит
локальную эксклюзивную блокировку. Все записи кнопками и голосом используют общую
блокировку чтения/изменения ячейки, расчёты выполняются через Decimal, на границе
Google API значения преобразуются в JSON-числа.

**Google Sheets и SQLite не образуют общую транзакцию.** Если ответ Sheets потерян
или процесс завершился между записью и отметкой в журнале, соответствующая операция
помечается «результат неизвестен». Автоматического повторения нет, оставшиеся
операции не выполняются. Сверьте отмеченные суммы в таблице вручную перед новым
вводом. Повторное нажатие на исходное подтверждение безопасно. Редактирование
таблицы другими приложениями не участвует в локальной блокировке.

Транскрипт удаляется из записи после завершения/отмены и при обработке истёкших
пакетов. Журнал операций и ключи дедупликации сохраняются в `data/voice.sqlite3`.
Не удаляйте эту базу при развёртывании. База содержит финансовые суммы; каталог
должен быть доступен только пользователю бота.

## Проверки и диагностика

Обычные тесты работают офлайн с fake/mock для всех внешних сервисов:

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m unittest discover -v
.venv/bin/ruff check .
.venv/bin/ruff format --check .
```

Реальный smoke test выполняется отдельно. Он использует синтетическое аудио,
настоящие STT/Hermes и подменённые Telegram/записи. В рабочую таблицу ничего не пишет:

```bash
export VOICE_BRIDGE_COMMAND='["docker","exec","-i","hermes-agent-owxa-hermes-agent-1","/opt/hermes/.venv/bin/python","/opt/data/scripts/accounting_voice_bridge.py"]'
.venv/bin/python scripts/smoke_voice.py --audio /tmp/accounting-voice-smoke.ogg
# Только проверка Hermes, без аудио:
.venv/bin/python scripts/smoke_voice.py
```

Для полного теста аудио должно содержать пример с магазином на 1000 бат и бензином
на 500 бат. Стандартные тесты никогда не запускают этот скрипт.

В журнале службы: этап `stt`/`parse`/`pending`/`write`/`result`, длительность,
идентификаторы пакета и сообщения, безопасный тип ошибки. Для ошибок кнопок также
записываются файл, строка и функция, где произошёл сбой. Текст исключения,
локальные переменные и строки исходника в лог не включаются. Аудио, транскрипт,
ответ модели, URL с токеном и полный traceback в обычные логи не выводятся.
Если voice недоступен, проверьте состояние контейнера и выполните smoke test.
