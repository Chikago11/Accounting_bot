# Accounting bot

Telegram-бот учёта расходов в Google Sheets: категории, месячный отчёт,
отдельные бюджеты Андрея и Макса. Вход разрешён только `ALLOWED_USER_IDS`.

## Запуск

Python 3.12, зависимости из `requirements.txt`:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
chmod 600 .env service_account.json
.venv/bin/python main.py
```

Заполните `.env`: токен, `SPREADSHEET_ID` существующей таблицы, JSON-ключ Google
и разрешённые Telegram ID. ID берётся из адреса `.../spreadsheets/d/<ID>/edit`.
При пустом ID сохранён старый поиск по `SPREADSHEET_NAME`; при указанном ID имя
не используется. Ошибка доступа по ID не переключает бота на другую таблицу.
Требуются первый лист с матрицей расходов и лист `andrei_mb`
(B1 — Андрей, B2 — Макс). Секреты и каталог `data/` исключены из Git.

`APP_TIMEZONE=Asia/Bangkok` задаёт общий часовой пояс для кнопок, отчётов и голоса,
в том числе при ручном запуске на сервере с UTC. Если `APP_TIMEZONE` не задан,
поддерживается прежний `VOICE_TIMEZONE`, затем используется `Asia/Bangkok`.
Часовой пояс проверяется при загрузке конфигурации, даже при выключенном голосе.
Опечатка в названии не позволяет запустить бота до исправления настройки.
Кнопки принимают только положительные суммы: прибавление или вычитание определяет
выбранное действие. Числовые ячейки читаются без оформления валюты и разделителей;
отображение заголовков месяцев пока должно оставаться `YYYY-MM`.
Версии прямых зависимостей закреплены в `requirements.txt`, а полный набор пакетов
рабочего бота — в `constraints.txt`. Ограничения подключаются автоматически при
установке `requirements.txt`, в том числе при сборке Docker-образа. База Python
зафиксирована по digest в `Dockerfile`. Обновляйте эти версии вместе после проверки
чистой сборки и тестов; `constraints.txt` снимайте с проверенного рабочего образа,
а не из окружения разработки с дополнительными пакетами.

При первой записи в новый месяц бот создаёт текстовый заголовок `YYYY-MM` и
формулу `SUM` в строке «Итого», найденной по названию. Диапазон суммы — от второй
строки до строки перед «Итого». Заголовок и формула отправляются одним
[пакетным запросом Sheets](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/batchUpdate).
Заранее заданная формула в «Итого» сохраняется. При занятых ячейках нового столбца
бот просит проверить таблицу. Существующие месяцы автоматически не переделываются.

Категория должна уже присутствовать в таблице в единственном экземпляре перед
«Итого». Недостающие строки бот не добавляет: добавьте категорию вручную и
проверьте диапазоны итоговых формул. Ошибка структуры выводится пользователю;
отклонённая голосовая операция отмечается как незаписанная.
При записи расхода в ячейку с ручной формулой бот использует её вычисленную сумму
и сохраняет новое итоговое число. Слагаемые не сохраняются.

На текущем сервере бот запускается через `compose.yaml`; подготовка описана ниже:

```bash
docker compose ps
docker compose restart bot
docker compose logs -f bot
```

Штатная остановка через SIGINT завершает обработку и закрывает приложение без
traceback `KeyboardInterrupt`; остальные исключения не подавляются.

## Голосовой ввод

Отправьте боту голосовое, например:

- «Добавь расход на магазин тысячу бат и на бензин пятьсот бат».
- «Отмени расход на бензин двести бат».
- «Добавь в бюджет Макса триста бат и вычти из бюджета Андрея сто».
- «Вчера потратил на продукты пятьсот бат».
- «Покажи бюджет Андрея», «сколько осталось у Максима», «покажи оба бюджета».
- «Покажи отчёт за месяц» или «отчёт за прошлый месяц».
- «Открой отдельные бюджеты», «меню бюджета Андрея», «главное меню», «назад».

Показ остатков, отчёты и переходы по меню выполняются сразу. Для изменений денег,
распознанных из голосового, бот показывает расшифровку и список операций; запись начинается после
кнопки «Подтвердить». «Изменить» отменяет пакет и предлагает меню или новое голосовое.
«Отмена» ничего не записывает. Неясная команда вызывает уточнение всего пакета.

Без суммы команда «Добавить бюджет Андрея» открывает тот же запрос суммы, что и
кнопка. После неё можно ответить голосом «пятьсот» — бот подготовит пополнение на
500 THB для подтверждения. Работает и выбор категории: «добавить расход» →
«супермаркет» → «двести пятьдесят». Контекст учитывает и голос, и нажатия кнопок.
Ответ суммой обычным текстом использует прежний кнопочный сценарий прямой записи.
Диалог выбора хранится в памяти, как раньше для кнопок; после перезапуска выберите
действие снова. Уже подготовленные пакеты подтверждения сохраняются в SQLite.

Все пункты текущего меню имеют голосовые команды. Тест сверяет покрытие с `MENUS`,
чтобы новое действие в кнопках не осталось без голосового маршрута.
Остатки и отчёты читаются теми же функциями, что используются кнопками, без
передачи финансовых данных Hermes.

Можно сказать «Добавь Максу 300 бат и покажи его остаток»: сначала будет
подтверждение записи, затем актуальный остаток. При ошибке записи последующие
запросы не выполняются. Повторное подтверждение не повторяет запись; запрошенный
остаток/отчёт может быть показан ещё раз. Команду открытия меню или запроса
недостающей суммы отправляйте отдельно от других действий.

Поддерживаются существующие операции: добавить/отменить расход, добавить/вычесть
из двух отдельных бюджетов. Доходы/зарплата, конвертация валют и новые категории
не добавлены. Отчёты и чтение остатков доступны голосом и кнопками. Валюта — THB,
даты — Asia/Bangkok. Расходы можно отнести к дате за последние 366 дней; в таблице
они суммируются по месяцу. Отдельные бюджеты хранят текущий остаток без истории.

Ограничения: до 120 секунд, 10 МБ, 10 операций, 10 000 000 THB на операцию,
два десятичных знака. Подтверждение действует 15 минут. Одновременно распознаётся
одно голосовое; кнопочный интерфейс доступен во время распознавания.

## Архитектура

```text
Telegram voice → текущий бот → STT (GigaAM в Hermes)
  → Hermes без инструментов → строгий JSON → локальная проверка
  → SQLite pending → подтверждение → transactions.py
  → существующие google_api.py → Google Sheets
```

`catalog.py` — единственный список категорий для кнопок и модели.
`category_aliases.json` — редактируемые разговорные синонимы этих категорий.
Hermes получает только текст, категории, действия, валюту и время. Telegram-токен
и Google-ключ остаются в боте. Второй Telegram consumer не запускается.

`voice/providers.py` содержит интерфейсы STT/парсера и транспорт JSON через HTTP.
Бот работает в отдельном контейнере от UID/GID 1000, без Docker-сокета и дополнительных
прав, с системными файлами только для чтения. Запись разрешена в `data/` и временный
`/tmp`; `.env` и Google-ключ подключены только для чтения и не включаются в образ.

Во внутренней сети Hermes `scripts/hermes_voice_server.py` слушает порт 8646:
`POST /voice` принимает только `transcribe` и `parse`, `GET /health` проверяет запуск.
Оба адреса требуют отдельный Bearer-ключ. Порт не публикуется на хосте. Произвольные
команды, пути к файлам и смена модели через запрос запрещены; запросы ограничены
по размеру, времени и выполняются по одному.

HTTP-сервер запускает существующий `scripts/hermes_voice_bridge.py` отдельным
процессом под пользователем `hermes` внутри контейнера Hermes. Сохраняется headless
`AIAgent` с `enabled_toolsets=[]` и проверкой пустого списка инструментов, без памяти
и сохранения сессии. Временное аудио и дочерние процессы удаляются также при
таймауте или обрыве HTTP-соединения. Провайдер берётся из
текущей настройки Hermes, STT — из его настроенного GigaAM. Модель разбора команд
бота задаётся через `HERMES_MODEL`; на этом сервере используется `gpt-5.6-luna`.
Для HTTP модель должна совпадать с `HERMES_MODEL` службы моста. Адаптер проверяет выбранную модель;
её несовпадение считается ошибкой разбора. Общая настройка модели Hermes не меняется.
Отдельное «назад» (также «вернись назад», «верни назад») обрабатывается кодом по
состоянию диалога: от ввода суммы расхода — к выбору категории, затем в главное
меню; из ввода суммы бюджета — в его меню, затем в список бюджетов.

Этот адаптер зависит от установленного Python-интерфейса Hermes. После обновления
Hermes следует запустить smoke test. Транспорт можно заменить реализацией тех же
интерфейсов без изменения обработчиков и финансовых функций.

## Запуск в Docker на этом сервере

Сначала создайте отдельный ключ моста; секреты не выводятся в терминал:

```bash
python3 - <<'PY'
import os
from pathlib import Path
import secrets
Path("data").mkdir(mode=0o700, exist_ok=True)
path = Path(".voice-bridge.key")
if not path.exists():
    with os.fdopen(os.open(path, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600), "w") as stream:
        stream.write(secrets.token_urlsafe(32))
PY
```

Скопируйте адаптеры и ключ в сохраняемый том существующего Hermes:

```bash
docker exec hermes-agent-owxa-hermes-agent-1 mkdir -p /opt/data/accounting-voice
docker cp scripts/hermes_voice_bridge.py \
  hermes-agent-owxa-hermes-agent-1:/opt/data/scripts/accounting_voice_bridge.py
docker cp scripts/hermes_voice_server.py \
  hermes-agent-owxa-hermes-agent-1:/opt/data/scripts/accounting_voice_server.py
docker cp .voice-bridge.key \
  hermes-agent-owxa-hermes-agent-1:/opt/data/accounting-voice/bridge.key
docker exec hermes-agent-owxa-hermes-agent-1 chown -R hermes:hermes /opt/data/accounting-voice
docker exec hermes-agent-owxa-hermes-agent-1 chmod 700 /opt/data/accounting-voice
docker exec hermes-agent-owxa-hermes-agent-1 chmod 600 /opt/data/accounting-voice/bridge.key
```

Установите службу, которая поддерживает HTTP-мост внутри Hermes:

```bash
mkdir -p ~/.config/systemd/user
install -m 644 deploy/accounting-voice-bridge.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now accounting-voice-bridge.service
```

У пользователя запускающего эту службу должен быть доступ к Docker и включён
linger. Служба выполняет одну фиксированную команду `docker exec --user hermes`;
обработчик HTTP находится внутри Hermes. Сам бюджетный бот доступа к Docker не получает.
После остановки/перезапуска Hermes служба повторно запускает мост. Профили других
приложений и основной процесс Hermes перезапускать не требуется.

В `compose.yaml` уже заданы внутренняя сеть Hermes, URL, путь к ключу, Luna и лимиты.
`.env`, `service_account.json` и `data/` остаются в папке проекта. UID/GID 1000
совпадает с владельцем этих файлов на данном сервере; при переносе на другой
сервер согласуйте владельца каталога данных и пользователя контейнера.

Подготовьте образ и проверьте мост, затем остановите старый polling-процесс:

```bash
docker compose build bot
docker compose run --rm --no-deps bot python scripts/smoke_voice.py
systemctl --user disable --now rich-family-bot.service
docker compose up -d bot
docker compose logs --tail 30 bot
```

Бот автоматически стартует с Docker (`restart: unless-stopped`), мост — с user systemd.
Одновременно запускать контейнер бота и старую службу нельзя: они используют один
Telegram-токен и одну SQLite-базу. Контейнер подключает прежний `data/` напрямую,
поэтому сохраняются ожидающие подтверждения и защита от повторной записи.

Обновление кода: `docker compose up -d --build bot`. Обновление серверного адаптера:
повторите копирование двух скриптов и перезапустите `accounting-voice-bridge.service`.
Для смены модели измените её одновременно в Compose и службе моста.

Старый транспорт `VOICE_BRIDGE_COMMAND` сохранён для отката. Остановите контейнер
(`docker compose stop bot`) и только затем включите прежнюю службу
(`systemctl --user enable --now /home/alfred/projects/Accounting_bot/deploy/rich-family-bot.service`).
Unit хранится в `deploy/rich-family-bot.service`; установленная ссылка systemd указывает
на этот файл. Её drop-in с командой
`docker exec` сохранён на сервере. Такой откат возвращает прежние широкие права процесса.

Остановка через SIGINT имеет запас 240 секунд. При принудительной остановке
незавершённая запись восстанавливается как неопределённая по журналу.

## Повторы и ошибки записи

SQLite сохраняет уникальность исходного сообщения, владельца пакета, срок действия
и результаты отдельных операций. Подтверждение атомарно переводит пакет в
`processing`; повторный callback возвращает результат. Рабочий процесс держит
локальную эксклюзивную блокировку. Все записи кнопками и голосом используют общую
блокировку чтения/изменения ячейки, расчёты выполняются через Decimal, на границе
Google API значения преобразуются в JSON-числа.

**Google Sheets и SQLite не образуют общую транзакцию.** Если ответ Sheets потерян
или процесс завершился между записью и отметкой в журнале, соответствующая операция
помечается «результат неизвестен». Автоматического повторения нет, оставшиеся
операции не выполняются. Сверьте отмеченные суммы в таблице вручную перед новым
вводом. Повторное нажатие на исходное подтверждение безопасно. Редактирование
таблицы другими приложениями не участвует в локальной блокировке.

Транскрипт удаляется из записи после завершения/отмены и при обработке истёкших
пакетов. Журнал операций и ключи дедупликации сохраняются в `data/voice.sqlite3`.
Не удаляйте эту базу при развёртывании. База содержит финансовые суммы; каталог
должен быть доступен только пользователю бота.

## Проверки и диагностика

Обычные тесты работают офлайн с fake/mock для всех внешних сервисов:

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m unittest discover -v
.venv/bin/ruff check .
.venv/bin/ruff format --check .
```

Реальный smoke test выполняется отдельно. Он использует синтетическое аудио,
настоящие STT/Hermes и подменённые Telegram/записи. В рабочую таблицу ничего не пишет:

```bash
docker compose run --rm --no-deps \
  -v /tmp/accounting-voice-smoke.ogg:/tmp/smoke.ogg:ro \
  bot python scripts/smoke_voice.py --audio /tmp/smoke.ogg
# Только проверка Hermes, без аудио:
docker compose run --rm --no-deps bot python scripts/smoke_voice.py
# Проверка фраз для всех меню, бюджетов, отчётов и диалогового ввода суммы:
docker compose run --rm --no-deps bot python scripts/smoke_voice_commands.py
# Проверка синтетического аудио «Покажи бюджет Андрея» через настоящий STT:
docker compose run --rm --no-deps \
  -v /tmp/budget-show.ogg:/tmp/budget-show.ogg:ro \
  bot python scripts/smoke_voice_commands.py --case andrei_show --audio /tmp/budget-show.ogg
```

Для полного теста аудио должно содержать пример с магазином на 1000 бат и бензином
на 500 бат. Стандартные тесты никогда не запускают этот скрипт.

В журнале службы: этап `stt`/`parse`/`pending`/`write`/`result`, длительность,
идентификаторы пакета и сообщения, безопасный тип ошибки. Для ошибок кнопок также
записываются файл, строка и функция, где произошёл сбой. Текст исключения,
локальные переменные и строки исходника в лог не включаются. Аудио, транскрипт,
ответ модели, URL с токеном и полный traceback в обычные логи не выводятся.
Если voice недоступен, проверьте состояние контейнера и выполните smoke test.
